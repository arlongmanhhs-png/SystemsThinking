# Step 6. Analyse the mapping and write its narrative

**Not yet written.** This file holds what is settled about the step: what it is
for, its critical check and its sources. What the participant does, in what
order and with what guidance, is written phase by phase in the working document
and comes here after it is settled. Do not build from this file alone.

## What the step is for

Explains why the system behaves as it does.

## Output

Named loops, archetypes, mental models, narrative

## Uses the output of

Step(s) 2, 3, 5. See `core/critical-checks.md` for the dependency table and the
return triggers.

## The critical check

The step is complete when:

- Each loop is named and explained.
- Any recognised system trap is identified (Meadows' eight).
- Non-linear relationships are noted.
- The narrative explains the pattern from Step 3.
- The mental models behind the structure are stated, and the goal that the system's behaviour implies is named, whether or not anyone intends it.

The criteria are self-checked. See `core/critical-checks.md`.
